# 选片短视频打卡流程

## 1. 用途与交付

- **适用场景**：按用户指定日期（或每天 20:00 定时查次日 ERP 选片表）连续交付整张选片表的客户打卡短视频。
- **必要输入**：目标选片日期（默认次日）；本机配置（ERP 入口、NAS 挂载根目录等）从外部配置传入。
- **交付产物**：
  1. 每单新制成片 `抖音打卡送彩票.mp4` 排他新增回存至该单最近一次有效拍摄的**原 NAS 底片目录根部**（已有成片不覆盖、直接复用原链接）；
  2. 按 ERP 原序排列的汇总表：`年度底片/选片打卡报表/YYYY年M月D日视频总表.html`（含跳过客人的已有视频相对链接，批末读回校验）；
  3. 逐单确认回存与登记后，清理本机临时照片副本与剪映工作草稿（母版、运行记录与原片严格保留）。

## 2. 环境、配置与边界

- **支持平台**：macOS 已完成多批真实订单连续交付验收；Windows 与独立无人值守尚未验收。
- **本机非同步工作目录**：默认使用仓库外的 `~/Documents/ChatGPT/StudioData/outputs/studio-checkin-video/YYYY年M月D日选片/`（替代原先直接堆在 `~/Documents/` 根下的做法；避免放入 iCloud 同步目录），内设 `运行记录/queue.db` 驱动整批状态机。
- **协同技能调用链**（统一使用 `studio-` 前缀新名称）：
  - 底片匹配与复制：调用 `$studio-photo-folder-match`
  - 25/22 张儿童构成选片：调用 `$studio-photo-selection`
  - 22 槽母版替换、导出与草稿清理：调用 `$studio-jianying-bts-editor`
  - 指定使用局域网 Ollama 时遵循 [references/local-model.md](references/local-model.md)。

## 3. 执行步骤（整表连续驱动）

**每次执行的交付单位是整张 ERP 选片表。** 通过 [scripts/day_queue.py](scripts/day_queue.py) 管理状态流转：先完成全表匹配（`match`），再完成无视频订单的整批本机复制（`copy`），随后逐单连续执行 `select → edit → archive → report → clean → done`。每步完成后立即调用 `advance` 取下一动作并在同一会话继续，结束前必重读队列，直至返回 `check_report` 或剩余全为 `blocked`。

1. **查表与队列初始化**：确认 ERP **报表标题**已加载目标日期（防旧缓存），按原序提取单号、时间、家长/宝宝全部姓名、摄影师及重拍备注，同单重复排期按轮次去重。空表即结束；非空表运行 `python3 scripts/day_queue.py <queue.db> init KEY1 KEY2 ...`。
2. **全表匹配（`match`）**：用 `$studio-photo-folder-match` 定位原 NAS 底片目录（排除问号改期与成长套历史已完成轮次；整轮重拍只取最后一次有效实拍）。源目录根部已有打卡视频（如 `抖音打卡送彩票.mp4`）直接走 `match → report` 登记原链接，跳过复制与制作。
3. **批量复制与修后提取（`copy`）**：将所有无成片的就绪订单复制到本机工作目录并比对路径与大小。**仅在本机副本内整理**：存在「已修」「魔镜修图」等明确修后目录时，提取修后图到本单工作根并**只从修后照片挑选**（不足 25 张时 `block` 记录待询问；同名不同内容加 `_已修`）。
4. **选片（`select`）**：用 `$studio-photo-selection` 按儿童打卡构成规则（优先 1–2 张全家福、合照 ≤ 3 张、成人单人照不入选）锁定 25 张保留名单放入本单 `视频打卡/`，并锁定其中 22 张上片子集与槽位映射。
5. **剪映套版导出（`edit`）**：用 `$studio-jianying-bts-editor` 在母版独立副本中逐槽替换 22 张照片，导出到本单 `视频打卡/抖音打卡送彩票.mp4`；确认导出完成页且 MP4 非空即进入回存。
6. **回存与更新总表（`archive` → `report`）**：将 MP4 排他新增回原 NAS 拍摄目录根部（核对字节大小一致，同名不覆盖），随即更新当日 `视频总表.html`（相对路径经 URL 编码）。
7. **逐单清理（`clean`）**：已获用户授权在打卡视频交付后清理本批工作副本，无需逐单再确认。确认 NAS 成片非空、与本地文件大小一致，且总表链接指向该成片后，按断点核对草稿名称，将本次工作草稿移入剪映「最近删除」，再清理本次创建的本机照片副本、预览与本地 MP4。保留运行记录、剪映母版和 NAS 原目录。合单时核对所有关联订单链接后，只清理一次共用素材和草稿。核实清理结果后才推进到 `done`，失败时记录断点并继续其余订单。批末收到 `check_report` 时统一读回共享总表核对全部行与目标非空。

## 4. 验收与异常恢复

- **完成标准**：ERP 确认空表，或整表所有可执行订单均核实 NAS 成片非空、当日 HTML 总表读回无误，并完成本批工作副本清理。
- **单客阻碍隔离与续做**：单笔订单遇目录歧义、修后不足或挂载失败时，立即用 `day_queue.py <db> block <KEY> "具体原因"` 挂起该单并继续下一单，绝不因一单卡死整批。常见故障恢复见 [references/troubleshooting.md](references/troubleshooting.md)。
