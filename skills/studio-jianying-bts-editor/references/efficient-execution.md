# 多批次执行：减少模型往返

version: 26.10.13

## 启动快路径

先用已知路径检查和加载必需文件，同一会话未变化的内容不重复全文读取。已有映射且照片未变化时，核对文件存在、非零及排序依据后复用；不重新选片或重新创建映射。本技能使用自带规则与 `LOCAL_DEPLOYMENT.md` 指向的外部部署记录，不加载 Core/Foundation，不对整个 `/Users` 或用户主目录执行递归搜索。读取规则、检查挂载和素材等独立只读步骤可并行。

本机已验证剪映主程序入口为 `/Applications/VideoFusion-macOS.app`，优先 `cua.getApp` 直接连接；“剪映”不是有效应用名，`com.lemon.lvpro` 会匹配多个内嵌程序。仅入口失效时再列应用并重新定位。进入编辑器后截图刷新窗口几何，坐标必须以当前会话观察为准。

同一会话已有目录写权限时直接使用，确实缺少时才一次申请本任务需要的状态目录与输出目录。分别记录准备、权限等待、制作、导出和清理；既有 11 分 45 秒准备记录没有细分，不能全部归因于读取规则或技能本身。

## 开始与复用

首批核对当前模板、窗口布局和替换入口。已证明批量替换可用才使用；不可用则逐位替换，不在每批重试同一个不支持的入口。把已验证的操作函数保存为工作区中的可恢复代码，通过当前授权 UI 工具执行；不改剪映私有草稿文件。

函数显式接收 `batch_id`、槽位和映射，不依赖上一次批次的全局目录变量。每个槽位用确切路径匹配、核对已选文件、确认“复用原视频效果”，确认替换完成后再记入 completed。导入后尚未确认的照片记为 pending，不能提前记为完成。

使用 `scripts/batch_session.mjs`：`createBatch({source, materials, output, selected})` 接收本批绝对路径和按顺序的 22 个 `{slot, source}`，生成冻结映射及内容摘要。素材不在默认 `source/123` 时，显式传入 `materials` 绝对目录（例如 `source/已选`）；每张来源仍须严格匹配该目录。`initialState(batch, draftName)` 初始化断点。每段调用 `runSegment({batch, state, replace})`；替换适配器签名为 `replace({batch, row})`，导出函数也直接接收当前 batch。所有函数只使用传入对象，禁止闭包读取 REPL 中可被重新绑定的 `batches`、当前目录或旧批次索引。

替换适配器必须读取当前 UI：核对路径输入框的实际值、选择器已选行的完整文件 URL、效果选项，以及提交后编辑器重新出现，才返回 `{slot: row.slot, source: row.source, submitted: true}`。`selectedFileMatches(ax, row.source)` 比较已选行解码后的完整 URL；同名文件、其他行里出现路径、仍停留路径输入框都不能作为选中依据。当前 AX 未提供完整路径时，通过当前 UI 获取可核对的文件位置，不降级为仅比文件名。布局坐标仍需当前截图依据。

在支持 Node 模块导入的已授权 UI REPL 中导入该模块；不使用 eval 或动态生成函数。若工具不支持模块导入，保留相同显式参数与断言，直接定义可审阅函数。模块本身既不控制剪映，也不读写断点文件。

## 复用已验证替换流程

`scripts/cua_replace.mjs` 把 2026-10-27 的逐位替换流程固化为 `createReplacer({app, layout, onEvent})`，返回可直接传入 `runSegment` 的适配器。所有输入仍由已授权 cua_repl 的 app 方法执行。无需重新生成函数、重新探测已证实不可用的批量入口。

首槽读取当前编辑器、替换对话框截图，核对“复用原视频效果”开启后构造 layout：`{verified:true, timeline:[[x,y],...22项], editorSize:[宽,高], dialogSize:[宽,高], submit:[x,y]}`。尺寸是当前截图 PNG/JPEG 的像素尺寸，不预设屏幕缩放。该模块逐次截图核对尺寸；不支持的图片格式或布局变化返回异常，需要人工式界面观察后重新绑定，不能自动套用旧坐标。

替换弹窗可能短暂处于中间尺寸。只在已识别的替换弹窗中重新读取AX和截图，最多3次截图观察，总观察预算1.5秒，不固定睡眠。编辑器尺寸不符不自动恢复；未知窗口或持续尺寸不符立即返回pending，不在不稳定尺寸下点击。预算约束后续观察的启动，不能硬取消正在运行的UI工具。每次尺寸变化记录 `geometry-mismatch` 的槽位、阶段、期望/实际尺寸、读取次数和耗时。点击提交后若AX仍是替换弹窗，先再次观察：编辑器已经出现就不再点击；仍在已确认尺寸的替换弹窗才补一次提交，最多补一次。仍未完成则停止该段。这属于操作状态恢复，不启动成片画面质检。

适配器的 `slot-timing` 事件记录 `open_chooser / select_file / import_dialog / submit / total` 耗时，失败时保留发生阶段。成功 proof 携带 `timings_ms`，调度器将最近22槽保存到 `slot_metrics`；异常保存 `failed_slot_metrics`。正常只返回完整机器状态及简短进度，不逐槽解释日志；计时不额外增加截图或AX读取。用这些数据区分真正的UI耗时与段间模型/工具编排耗时。

选择器先用 `fileEntryIndex` 在当前AX找完整文件URL：已选中则直接导入；目标已列出则点击当前索引，读取新AX核对选中URL；未列出或点击后仍未选中才执行完整路径导航。不能按同名文件替代完整路径核对。事件 `file-selection` 记录实际走的 `already-selected / direct-file-entry / full-path-navigation`，便于判断是否真正减少导航。直接选片已于第三轮真实验证，正常5张约35秒。

```js
// 在已绑定 app、已观察 layout 的授权 cua_repl 中执行；skillDir 为实际技能绝对路径。
var session = await import(skillDir + '/scripts/batch_session.mjs');
var ui = await import(skillDir + '/scripts/cua_replace.mjs');
var replace = ui.createReplacer({app, layout});
var result = await session.runSegment({batch, state, replace});
nodeRepl.write(result);
```

首次手动完成一槽后，把该槽记为 completed，再接入适配器，不能重复替换首槽。相同布局的后续批次复用函数，但传入新的冻结 batch；改变窗口、平台或缩放后重新观察布局。

## 操作粒度与输出

- 每次改变界面后仍读取当前状态，下一动作的索引来自最新 AX；坐标有当前截图依据。只有工具文档支持时使用 `emit:false`，这只减少回传，不跳过观察。
- 在一次工具调用内执行若干带断言的确定性动作。默认分段预算52秒、最多6个槽位，工具超时设60秒；首次估算每槽15秒，之后按最近3槽最慢耗时乘1.25预留。稳定每槽7秒时可完成6槽约42秒，每槽9.6秒时通常可完成5槽约48秒。工具超时较短时降低预算并显式传给分段模块。现有断点只预约更少槽位时，以预约范围为上限；保存下一段后才可使用新范围。适配器也须为每槽动作设置界限，单次卡顿可能超出估算，预算不是硬取消机制。不要把整批22张塞进一次调用。
- 正常段只回传 `batch / completed_slots / pending_slot / next_step`。全量 AX 留在工具内解析；缺失控件、路径不符、未知窗口等立即停在当前槽位，回传精简错误及必要截图。
- 默认不输出逐张替换预览或合并画面审阅。仅通过文件匹配、提交状态及槽位进度确认替换操作；画面质量交由用户人工检查。用户明确要求质检时才审阅必要画面。
- 首次布局、弹窗变化、异常定位需要截图；相同布局正常推进无需反复输出整窗截图。不得为省截图绕过 UI 工具的观察要求。

## 断点

每段结束将以下信息原子写入工作区状态文件（先写临时文件，再替换），与素材映射保存在一起：模板/工作副本标识、batch、completed_slots、pending_slot、last_verified_step、next_step、output_path、blocker、cleanup_status。仅在对应动作已验证后推进状态。

先在有权限的文件工具或终端验证断点目录可写。UI REPL没有写权限时，由工具返回完整机器状态，在终端持久化；禁止把保存函数静默替换成空函数。使用 `scripts/checkpoint.mjs` 的 `advanceCheckpoint(file, result)`：一次原子写入本段实际completed/pending，同时将下一段最多6槽登记为 `inflight_slots`；失败或pending状态不预约下一段。首次调用传initialState，先写断点再开始UI。后续“本段完成后保存”和“下一段前登记”合并为一次工具调用，不再前后各单独调用。写入失败不得继续UI。

CLI 为 `node scripts/checkpoint.mjs STATE_PATH < result.json`；result.json 是工具返回的真实状态，使用安全文件写入工具或正确 shell 引用传递，不把 JSON 当 shell 代码拼接。也可在已授权且支持写文件的 REPL 中调用 API，实际写入失败则走终端桥接。每批独立状态文件；摘要、来源、输出路径或草稿名变化、进度回退均拒绝写入。显式恢复后才能清除 pending。

必须保存完整 result，包括 `samples_ms`、pending、blocker、实际事件及耗时；不要仅手动填写完成张数。运行环境确实允许写入时可调用 `runCheckpointedSegment({file,batch,replace})`，自动读取已预约范围、执行分段、保存完整返回值并预约下一段。2026-10-27 本机 cua_repl 写工作区状态文件返回 EPERM；同一权限环境内直接用终端桥接，不重复探测，不更换到未经授权路径。界面模块本身不需要 Node 全局 process，CLI入口已作环境判断。

`runSegment` 返回内存状态，不保证超时情况下的持久化。没有收到段结果时，已保存的 inflight 全部视为待核对，不能把旧 completed 当成真实界面进度直接重放。重新观察工作副本和可能触及的槽位，确定实际提交情况后记录恢复依据，清除 pending/inflight，再继续；无法确定则停止该批。恢复时必须匹配 batch 内容摘要、来源目录和输出路径，不允许把上一批断点用于下一批。

REPL 超时后重新绑定窗口并核对当前槽位、选择器与 pending，不盲重放整段。恢复代码和状态文件独立于 REPL，已有导出交付记录且文件仍存在、非零的成片跳过制作。工具超时只说明响应中断，不证明动作未执行。

## 默认直接交付

1. 核对素材数量、排序和槽位映射，按映射执行替换。
2. 替换提交完成后直接导出，不播放全片，不逐张或合并审阅画面。
3. 确认导出成功及目标文件存在、非零、路径和名称正确；不进行参数探测、解码、抽帧、试听或本地视觉调用。
4. 记录 `exported-awaiting-user-review` 与 `quality_check: skipped-by-user`。按 [草稿清理规则](../SKILL.md#短视频打卡完成后清理草稿) 处理本次副本。普通固定母版批次无需等待逐批确认。打卡批次先完成验收和最终路径核对。
5. 用户明确要求质检时才按指定范围启用检查；实际操作失败仍按断点和异常流程处理。

模型调用用于有判断的工作。计数、按 EXIF/文件名排序、固定命名、清单和报告格式用代码；有歧义的选片取舍再调用 reasoning。不要为加载了本地模型而让 Codex 再重复完成整套视觉分析。

## 验证范围

26.10.9 已于 2026-10-27 用一组经授权的样片22张实测：创建副本至导出完成观察 7分16秒，其中连续5张约41秒，导出完成观察约12秒；准备另计11分45秒，清理约52秒。第18、19槽确认弹窗各恢复一次。未做成片自动质检。

26.10.11 已使用保存的适配器真实复测同组22张，修复JPEG及跨运行时Buffer识别。创建副本至导出完成7分01秒，包含74秒现场修复；首次连接至导出7分34秒、清理38秒。正常5张约42秒，段间约13—16秒；逐张速度未明显改变。比上次制作快约15秒，总等待减少主要来自准备阶段复用，且两次权限/会话条件不同。扣除修复时间只可作为分项推算，不冒充另一轮完整实测。仍不承诺固定耗时或额度折扣。

26.10.12 同组第三轮：创建副本至导出5分33秒，首次连接至导出6分08秒；已保存完整耗时样本。选择器直接选片路径命中，正常5张约35秒，较上次正常5张约42秒缩短约17%。保留终端断点往返和第17槽尺寸变化恢复成本；上一轮含74秒修复，本轮总时间差只可按实际条件说明，不能全部当成选片提速收益。

26.10.13 已真实制作同组22张：首张单独确认，之后6+6+6+3张分4段，耗时42.1/42.9/40.9/22.1秒。第19槽638×526的中间尺寸自动再次观察至724×596后完成，无提交重试或主模型介入恢复。创建副本至导出5分32秒，与上次5分33秒基本持平；首次连接至导出5分42秒，清理后总计6分22秒。分步骤均值：打开选择器3.27秒、选文件1.15秒、导入弹窗1.30秒、提交1.33秒；后21槽均直接选文件。段间转存详细状态仍约92秒，不能因段数变少就声称总耗时已显著下降。此次验证的是6槽调度、尺寸恢复与计时功能实际可用。
