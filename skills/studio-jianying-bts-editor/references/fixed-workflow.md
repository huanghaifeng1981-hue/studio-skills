# 固定批次操作（26.11.4）

适用于已核对的22槽母版。11月1日记录240槽平均8.93秒，10月30日329槽平均8.15秒；整批完成间隔中位数分别7分25秒和4分44秒。此次段间平均23.4秒，说明优先减少编排往返；不同批次素材及环境不同，不能据此声称NAS或渲染变慢。

## 一次准备，每批复用

1. 核对挂载、原片和已有成片；按EXIF排序，缺失时说明文件序号依据。冻结22张映射。
2. 连接剪映，首页只读一次母版身份。复制母版，核对新副本；编辑器截图确认时间线布局。
3. 首槽核对替换弹窗和“复用原视频效果”，绑定 `createReplacer`。同一布局后续批次复用；不在每批重新编写流程。
4. 验证断点路径可写。如果UI REPL可写，直接使用checkpoint模块；只有实际写入失败才用终端桥接，不能把以前的EPERM当作当前结论。

## 正常循环

用 `batch_workflow.mjs` 的 `advanceWorkflow({file,batch,replace,adapters})` 推进一段或一个阶段。每次返回后立即进入下一段；不要插入单独的状态保存、再次读取同一状态、截图回传和长篇解释。用户进度更新按约60秒合并，不能省略当前UI核对。26.11.3将预算改为52秒/最多6槽，调用超时设60秒；预算不等于硬取消，不为凑6张盲目延长工具调用。

完成首槽验证并绑定适配器后，正常替换段统一调用下列形式，直接使用模块保存的断点，不再另跑终端读取或保存：

```javascript
state = await workflow.advanceWorkflow({file, batch, replace, adapters});
nodeRepl.write({phase: state.workflow_phase,
  completed: state.completed_slots.length,
  pending: state.pending_slot, blocker: state.blocker});
```

返回仍为replace且无pending/blocker时，下一工具调用立即执行相同语句。只有进入新阶段、异常或布局变化才回传必要截图并处理；不在正常段之间重新导入模块、重新解析素材映射或重新绑定适配器。不要将多个约38秒的段合成超过60秒的阻塞调用；不要靠省略UI状态断言加速。

调用超时不足60秒时，给 `advanceWorkflow` 显式传入较小的 `budgetMs`（例如45000），也可传 `maxSlots` 限制本段；两者会传至断点分段执行器。预算只允许大于0且不超过52000毫秒，仍保留给保存断点的余量；不能通过扩大参数绕过分段上限。低于单槽估算的预算会不执行UI，返回blocker及next_step=adjust-segment-budget；调整预算后再继续，不能原参数空转重试。

26.11.4由 `runCheckpointedSegment` 的finalize回调在写盘前补全阶段和计时，完成进度、指标与下一段预约只原子保存一次；不要在正常返回后重复调用advanceCheckpoint。独立调用runCheckpointedSegment仍自动保存，不可把finalize当作UI动作入口。

同一会话修改模块代码后，已有导入对象不会自动更新。需要现场验证修复时，把该模块及其相对依赖复制到工作区独立版本目录，再从新绝对路径导入；不要给本地导入路径追加查询参数尝试刷新。普通制作复用已加载且未变化的模块。

只有全部22槽确认、pending为空、无blocker才进入export。不要根据预计“本段会完成”提前开导出面板；11月1日曾只完成21槽就打开面板，需返回补齐。

阶段顺序：replace → export → confirm-export → cleanup → complete。阶段提交前保存phase_pending；超时或证明不符停止并核对真实界面，禁止重放整阶段。模块不执行UI动作；下列适配器通过授权UI调用实现，坐标来自当前截图，不能把历史坐标直接当真。

## 固定导出适配器

26.11.2：导出提交使用 `scripts/cua_export.mjs` 的 `createExportAdapter({app,layout,exists})`，layout传当前会话确认的size/title/folder/submit坐标；exists只做精确目标文件存在检查。由batch.output提取文件名，不写死客户或成片名。调用前显式打开导出面板并核对参数，完成页观察和清理仍分别确认。已完成真实UI复测；布局仍需按当前界面确认。

`export({batch,state})`：确认22槽后打开导出；当前截图核对1080P/30fps/H.264/MP4及云备份关闭。聚焦标题、全选、paste中文文件名，读取AX核对；点击文件夹入口，读取选择器，再打开前往文件夹、填batch.source、核对字段、一次Return、核对当前目录、点击打开。读取AX完整输出路径等于batch.output才提交。返回 `{output:batch.output,submitted:true}`。已有目标文件停止并核对，不覆盖。

`confirm-export({batch})`：读取完成页截图/AX，以完成页而非100%或回到编辑器为依据；stat目标文件非零。返回 `{output:batch.output,completed:true,bytes}`。保留默认人工验收，不播放、抽帧或解码。

进入清理阶段前按 [技能清理规则](../SKILL.md#短视频打卡完成后清理草稿) 核实交付条件。打卡批次仅在验收和最终路径核对均完成后执行清理。需要等待或按要求保留草稿时，将断点留在清理阶段并记录原因。

`cleanup({batch,state})`：关闭完成页、关闭本任务草稿；首页截图核对准确工作副本，右键删除，观察“最近删除保留30天”再确认；核对该副本离开列表、母版仍在、成片仍非零。返回 `{output:batch.output,draft_name:state.draft_name,cleaned:true}`。下一批从母版创建。

AX点击后状态未变，读取当前截图再用可见坐标一次，不重复无效AX点击；完整AX解析一律使用disableDiffing:true，普通diff不能作为全树匹配输入。替换弹窗延迟出现时保存pending，观察稳定后只提交当前槽，不重新导入。

## 计时与验证范围

26.11.2清理使用 `scripts/cua_cleanup.mjs`：调用前关闭完成页并返回首页；verifyHome依据当前截图核对本任务确切副本，返回draft_name/master_name/draftPoint/size；verifyDeleteDialog依据当前删除弹窗返回confirmed/submit。不把首卡位置或“副本”字符串当成身份。模块核对可恢复删除文案、母版保留及成片非零。所有动作仍通过授权app执行。

26.11.4清理前要求母版标题非空且不同于副本，二者都须在当前AX草稿列表中完整匹配；删除后重新按完整标题核对。仅包含母版名的“母版-副本”不算母版仍存在。此检查不代替verifyHome对当前截图及目标位置的确认。

阶段模块保存start/end/gap_ms。创建副本和准备也单独记起止，正常完成后统计单槽、段间、导出、清理，避免把准备和模型往返混算成剪映耗时。

需要效率报告时，复用 `scripts/workflow_metrics.mjs` 读取一个或多个断点：`node /实际技能路径/scripts/workflow_metrics.mjs /绝对路径/state.json`。它只读已有计时，不打开视频，不发起界面操作，也不覆盖断点。输出单槽均值、分段张数、执行及间隔时间、阶段记录；缺失或倒序时间为null，不能把缺失数据报告为0秒。总时长目前使用测试断点的test_started/export_observed_at/test_finished_at字段；普通旧断点没有这些字段时保持null，不推算完整批次总时长。只在需要分析效率时调用，不给正常每段增加独立统计往返。
