# 照片优选

## 1. 用途与交付

- **适用场景**：从指定源目录挑选精确 `N` 张照片（支持 `best` / `worst` 及横竖构图数量约束）；支持人工监督审美替换，以及上游儿童短视频打卡流程的 25/22 张构成挑选。
- **必要输入**：源照片目录、目标张数 `N`、方向（默认 `best`）、可选横竖比例约束，以及是否需要实际复制（默认只生成审阅计划，显式指定才复制）。
- **交付产物**：图像清单与 SHA-256 指纹、联系表预览、候选评估记录（`filename`、`score`、`reason`、`orientation`、`group`）及精确 `N` 张计划；任务中间文件统一保存在仓库外的 `StudioData/outputs/studio-photo-selection/`（或上游流程指定的任务目录），严禁写入源照片目录。

## 2. 环境、配置与边界

- **支持平台**：Python 3.9+（生成缩略图预览依赖已安装环境中的 `Pillow`；macOS 已完成 28 项自动测试及 155 张真实客片验收，Windows / Linux 实机待验证）。
- **模型与脚本分工**：
  - 具备视觉能力的助手模型（或显式配置的局域网 Ollama，见 [references/ollama.md](references/ollama.md)）负责审阅联系表与放大复核眼神/表情，填写主观评估 JSON；仅向已获授权的模型端点发送去除 EXIF 的缩略图。
  - 确定性脚本 [scripts/prepare_previews.py](scripts/prepare_previews.py)、[scripts/selection_tool.py](scripts/selection_tool.py)、[scripts/run_selection.py](scripts/run_selection.py) 负责枚举哈希、近似组去重、构图数量校验及防覆盖安全复制。
- **原片保护红线**：原片是唯一真源，严禁删除、移动、重命名或覆盖原片；复制拒绝非空目标目录、符号链接、路径穿越及源哈希变动。

## 3. 执行步骤

### 专项规则：儿童短视频打卡选片构成（仅在打卡视频流程启用）

- 先按画面区分：**孩子单人照**、**全家福**、**其他多人照（父子/母子等）**、**成人单人照**。
- **比例硬约束**：对 25 张保留名单与最终 22 张视频子集分别核对——每份名单优先保留 **1–2 张全家福（任何合照合计最多不超过 3 张，尽量不同构图）**，其余全部选孩子单人照；**成人单人照一律不入选**。
- 无合格全家福时可全用孩子单人照；孩子单人照不足时如实报告缺口，绝不多塞合照或重复照片凑数。

### 常规选片闭环

1. **建立清单与预览**：用 `scripts/prepare_previews.py` 只读枚举源目录直接包含的图像（排除子目录与符号链接），记录尺寸、方向与 SHA-256，按场景生成带文件名的联系表；读图失败明确记录，不凑数。
2. **分组审阅与眼神复查**：逐组审阅清晰度、曝光、表情、姿势与互动；**必须放大复查候选片中每位入镜人物的眼睛、视线与表情**（合照不能只看主角；非刻意闭眼或眼神涣散时优先同组替补）。
3. **构造确定性计划**：将近似连拍归入同一 `group`，调用 `scripts/run_selection.py`（底层 `SelectionTool.execute`）生成精确 `N` 张计划；默认仅输出计划（`status=review`），用户明确要求复制时才加 `--copy` 复制到空目标目录（`status=copied`）。
4. **反馈替换迭代**：用户对某张不满意时，将该张加入排除列表并记录原因，从同组或次优替补中补齐，保留上一版审计记录并重新校验张数、重复组与横竖约束。临时偏好只留本单，经用户确认长期采用的规则才写入外部审美配置。

## 4. 验收与异常恢复

- **完成标准**：入选数量精确等于 `N`、同一近似组不重复入选（除非规则允许）、横竖数量满足约束、复制后目标文件哈希与源文件一致。回归用例见 [tests/regression-cases.md](tests/regression-cases.md)。
- **中断恢复**：Ollama 批量看图支持 `--resume`（校验源哈希与模型一致后从断点续评）；复制或校验受阻时保留已有报告与部分副本，排查后改用新空目录或人工清理后重跑，不自动清空已有输出。
