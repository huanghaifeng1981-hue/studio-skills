# 照片文件夹查找

## 1. 用途与交付

- **适用场景**：根据用户提供的选片表或摄影表（拍摄表）图片及底片存放目录，查找每单对应的客人照片文件夹；默认**只读查找**，仅当用户明确要求复制并提供目标目录时执行复制。不包含照片审美挑选、套模板或视频导出。
- **必要输入**：排控表图片（选片表或摄影表）＋ 底片查找根目录（未提供时可读取外部配置 `StudioData/config/studio-photo-folder-match.json` 中的挂载盘提示，但须核实本次年份/月份，不拿历史月份当默认目标）。
- **交付产物**：
  - **只查找模式**：按原表顺序输出简洁核对表（区分`明确匹配`、`待确认候选`、`在所查目录中未找到明确匹配`、`未完成查找`）。
  - **复制模式**：仅输出一张结果表（`订单号｜客人｜目录｜结果`，区分`已复制`、`已存在，跳过`、`未找到`、`未完成`）。任务状态 JSON 保存在仓库外 `StudioData/outputs/studio-photo-folder-match/`，绝不写入源共享盘或目标照片盘。

## 2. 环境、配置与边界

- **支持平台**：Python 3.9+ 标准库运行（macOS 已在真实 SMB 共享盘验证防覆盖与中断恢复；Windows / Linux 走硬链接原子发布分支，待真实共享盘验证）。
- **模型与脚本分工**：具备视觉能力的模型负责识别表格类型与文字线索；目录遍历、精确姓名切分（`exact_name`）及断点续传复制统一由确定性脚本 [scripts/copy_photos.py](scripts/copy_photos.py) 执行。
- **只读与防破坏红线**：
  - 严禁修改、移动、重命名或删除源目录任何照片，不在源共享盘生成清单或隐藏缓存。
  - 不用浏览器打开 `afp://` 或 `smb://` 地址；若共享盘未挂载或无权限，提示用户先在系统中挂载，不索取密码、不绕过权限。
  - 起初只列目标目录的直接子目录名（`os.scandir` / `ls`），按需逐层向下查找客人目录，严禁一上来全盘递归扫描或读取大图。

## 3. 执行步骤

### 第一步：识别表格类型与字段（勿混用两类表）

截图被裁切时只处理可见完整行并说明范围；文字模糊时保留待核实，不凭相近字瞎猜，不抄录无关手机号或金额。

- **选片表**：提取`序号`、`订单号`、`选片预约时间`（注意不是拍摄日期）、`套系`、两个客人栏中的`全部姓名`（家长与宝宝均为检索候选）、`摄影师`。表内“美师”为“门市”的错别字，门市与“预选片”均不是摄影师。
- **摄影表（拍摄表）**：提取`表顶日期`、`订单号`、`拍摄预约时间`、`全部客人姓名`、`套系`、`预摄影/实摄影`（有实摄影优先按实际人员核对）、`拍摄状态`及补拍备注。
  - `未拍`：可能尚无本次照片，即使命中同名旧目录也须注明关联待确认。
  - `已拍完`或注明补拍：文件夹日期可能早于表顶日期，不能仅因日期不同排除姓名匹配目录。
  - 同订单多行预约：保留每行记录并关联同一查找结果，不擅自删行或当成两位客人。

### 第二步：目录匹配规则

文件夹通常形如 `2026.10.24r 严青青`（拍摄日期＋摄影师简称＋空格＋姓名，日期可不补零，简称可多字母）。

1. **只查找模式**：对每单所有家长名、宝宝名分别检索，保留目录完整原名；所查范围内**同名多个目录必须全部列出**（客人可能分次拍摄或有多笔订单）。仅姓名一致、同姓或近似字列为`待确认候选`；有独立线索（日期、摄影师、同单双名）相互印证且无冲突，或经用户确认本次归属时，才标为`明确匹配`。
2. **明确要求复制模式**：按完整姓名项精确匹配（[scripts/copy_photos.py](scripts/copy_photos.py) 的 `exact_name` 以空格/顿号/斜杠等分隔词项，严禁用子串匹配，如“王燕”绝不匹配“王燕玲”；字迹不清或仅姓氏命中不自动复制）。同名多目录全部纳入；同一源目录命中多行时只复制一次并关联各行。默认复制全部常见图片与 RAW（排除视频、隐藏文件及符号链接），已有同名文件跳过不覆盖。

### 第三步：安全复制与断点续传（复制模式）

状态文件统一放于 `StudioData/outputs/studio-photo-folder-match/<任务名>.json`：

```bash
python3 scripts/copy_photos.py plan \
  --source '/Volumes/米乐底片/2026年底片/10月' \
  --target '/Volumes/目标盘/指定目录' \
  --state "$HOME/Documents/ChatGPT/StudioData/outputs/studio-photo-folder-match/task-20261124.json" \
  --folder '2026.10.24r 客人姓名'

python3 scripts/copy_photos.py run --state "$HOME/Documents/ChatGPT/StudioData/outputs/studio-photo-folder-match/task-20261124.json"
python3 scripts/copy_photos.py report --state "$HOME/Documents/ChatGPT/StudioData/outputs/studio-photo-folder-match/task-20261124.json"
```

## 4. 验收与异常恢复

- **状态核对**：脚本逐文件原子更新状态（`copied` 本次复制成功、`existing` 原有同名跳过且未核对内容、`pending`/`failed` 未完成）。只有目录下全部计划文件均为 `copied` 才可报整目录“已复制”；空目录标为“未发现可复制照片”；权限或断连受阻标为“未完成”，绝不谎报为“未找到”或“已复制”。
- **断连续传**：单文件默认超时 120 秒（`--timeout` 可调），出错立即保存进度停止。网络盘恢复连接后，先核实源盘与目标盘挂载路径未变，再用原 `--state` 执行 `run` 从断点续传，同一状态文件只允许单进程运行。
