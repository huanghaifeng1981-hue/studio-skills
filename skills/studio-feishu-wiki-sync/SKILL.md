# 飞书知识库同步

## 1. 用途与交付

- **适用场景**：用户明确要求将本地单篇文档、指定栏目或整库「同步到飞书」（上传），或从飞书「更新本地」（下载）。每次只执行用户指定的一个方向。
- **必要输入**：同步方向（上传 / 下载）及目标范围（单篇文件、指定栏目或默认当前工作区知识库）。
- **交付产物**：两端内容对齐后的文档、写回本地页首 YAML 的 `feishu_url`，以及包含「更新 / 新建 / 跳过篇数与异常原因」的回读核验报告。

## 2. 环境、配置与边界

- **支持平台**：依赖调用方本机已安装并登录授权的 `lark-cli`（macOS 已在真实知识库完成双向验证；Windows / Linux 具备 `lark-cli` 环境时方法通用，待实测）。
- **身份与凭据**：读写飞书统一使用 `--as user` 代表当前登录用户操作；凭据由 `lark-cli` 本机管理，不在技能包内保存任何 Token 或门店映射表。授权过期或需扫码时遵循 [lark-shared.md](references/lark-shared.md) 生成链接与二维码。
- **安全边界**：
  - **只同步文档，不传播删除**：一端删除文件不会自动删除另一端页面（清理飞书页面须另走人工确认清单）。
  - **冲突先停**：两端均发生独立修改或覆盖依据不明时，先列出差异请用户确认，覆盖前遵循接收项目的旧版归档规则留痕。
  - **保护评论与内嵌资源**：更新已有飞书页面时优先按章节/块局部替换（见 [lark-doc-update.md](references/lark-doc-update.md)），非必要不使用整篇 `overwrite`，以免丢失页内评论或画板/表格引用块。

## 3. 执行步骤

执行命令前按需查阅包内参考：[共享与返回契约](references/lark-shared.md)（JSON 判断看 `ok == true` 而非 `code == 0`）、[读取 +fetch](references/lark-doc-fetch.md)、[更新 +update](references/lark-doc-update.md)、[新建 +create](references/lark-doc-create.md)、[Markdown 转义与传参](references/lark-doc-md.md)。

1. **读取接收项目约定**：先检查当前工作区的命名、版本与目录层级规则（如同名 Markdown 对应栏目首页、子文件夹对应飞书子页面、固定文件名 + 页首 YAML `version`）。
2. **定位对应原页**：
   - **优先匹配 `feishu_url`**：无论本地文件是否改名或移动，只要顶部 YAML 含有效 `feishu_url` 即对应同一飞书原页，不重复新建。
   - **首次匹配**：按对应栏目层级与标题查找同名页；确认缺失时才在目标父节点下新建；链接失效、无权访问或同名页不唯一时跳过并报告。
3. **按方向执行转换与写入**：
   - **同步到飞书（上传）**：读取本地正文，将文中指向其他本地 `.md` 的链接替换为目标文档已确认的 `feishu_url`（缺项如实注明，不上传本地死链或 `[[...]]` 源码）；按块更新或新建飞书文档。
   - **更新本地（下载）**：枚举目标飞书栏目及子栏目（取完分页），完整拉取正文后再落盘；保留本地 YAML 元数据（`version`、`status`、`implementation` 等）与固定文件名，将对应已知本地文档的飞书链接还原为本地相对链接 `[名称](相对路径.md)`。
4. **注意 `@file` 路径约束**：`lark-cli` 的 `--content @file` 仅接受当前工作目录下的相对路径（传绝对路径会报 `unsafe file path`），长文本优先通过 stdin `-` 或工作区相对临时文件传入，用完即清。

## 4. 验收与异常恢复

- **回读核验（必做）**：每次上传或下载写入后，必须回读核对标题、版本号、核心正文、关键表格及页内链接；首次建立对应关系后，将确认无误的飞书知识库链接写回本地页首 YAML 的 `feishu_url`。
- **中断恢复**：批量同步栏目时逐篇记录结果；单篇因权限或特殊块无法完整转换时跳过该篇并保留原状，继续其余可同步文档，最后汇总报告成功更新、新建与待人工处理清单。
