# 米乐摄影转档交接

本记录用于串联 AI 选片、Capture One 转档和逐张 AI 精修诊断。以下为技能试跑的字段约定。接入总控时可映射到项目实际数据结构。

| 记录 | 字段与用途 |
| --- | --- |
| 上游选片 | `photo_id`、`raw_path`、`selected`，分别对应稳定照片 ID、原始 RAW 路径和选中状态。沿用上游 ID，可保留评分用于追溯。 |
| 飞思处理 | `photo_id`、`raw_path`、飞思文档与变体 ID、实际全局与局部图层调整参数、飞思版本、技能版本、视觉模型及处理耗时。记录处理后读回值，变体保存在飞思。 |
| 皮肤润饰 | 按去瑕疵、均匀肤质、统一肤色分别记录实际工具、强度或样式、处理区域和结果。所有选中照片默认润饰，记录默认参数版本、源文档与变体及已应用、失败或异常待复核结果；不可见部位注明不可见，不以皮肤好为由跳过。注明仍需下游检查的问题。 |
| 参考依据 | 参考 JPG 与同名备注的库内路径及版本或日期、匹配布光的理由；新场景试转的样片、负责转档同事的确认人和日期。 |
| 转档质检 | `photo_id`、`status`、检查结果、已尝试修正次数、`verified_adjustment_seq`、`verified_sha256`、`handoff_valid`。终端状态为 `passed`、`needs_review` 或 `failed`；若已 `passed` 照片后续发生 `apply` 或 `rollback` 调参，交接记录会被实时降级为 `stale`（`handoff_valid=false`），须重新正式导出并登记后方可恢复 `passed`。 |
| 中间图 | `photo_id`、`output_path`、JPG 配方、原始完整画面预期尺寸、实际尺寸、无裁切/无缩放检查、ICC 色彩空间、配方质量读回值、输出版本及对应最终变体。固定原始完整画面与像素尺寸、质量 100、sRGB。 |

批次记录可保存为 JSON Lines，每张已选照片一行。照片 ID 重复、ID 与源路径冲突、选中标记不明确或源文件缺失时，先标出受影响记录，继续处理可确定的其他照片。独立重试前使用照片 ID、变体及输出版本查对现有产物。

每张通过的照片交接一份 JPG，曝光、蒙版和默认润饰合成在同一最终变体中导出。核对已选总数 = 通过数 + 待复核数 + 失败数，合格 JPG 数 = 通过数。只有 `passed` 且实际 JPG 通过可解码、规格和路径校验的记录才进入逐张精修诊断。待复核及失败记录留在转档环节供处理。`passed` 表示转档通过，客户选片仍须经过精修、整套 AI 质检和人工最终复核。

精修诊断结合交接 JPG 与润饰记录，按当前残留问题决定后续动作。已处理且达到标准的项目跳过。
